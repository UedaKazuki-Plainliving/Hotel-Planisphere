#### BUG-004　🟠 【重大】セッション管理の詳細（タイムアウト・Cookie属性）が未確認

| 項目 | 内容 |
|---|---|
| **ID** | BUG-004 |
| **種別** | セキュリティ脆弱性（セッション管理）|
| **深刻度** | 重大 |
| **発見テスター** | ④ セキュリティ観点 |
| **発見日** | 2026-04-27 |
| **対応状況** | 🔍 調査中（静的確認では詳細不明）|
| **対応担当** | TBD |

**概要：** ログイン後のセッション管理（タイムアウト時間・Cookie の Secure/HttpOnly/SameSite 属性）が静的解析では確認できない。

**確認が必要な項目：**
- Cookie に `Secure` フラグが設定されているか（HTTPS通信のみでCookieを送信）
- Cookie に `HttpOnly` フラグが設定されているか（JavaScriptからCookieにアクセス不可）
- Cookie に `SameSite` 属性が設定されているか（CSRF対策）
- セッションタイムアウトが適切に設定されているか

**確認手順：** ログイン後にブラウザのDevTools → Application → Cookies でCookie属性を確認する

**推奨対応：** Cookie属性を確認し、Secure・HttpOnly・SameSite=Lax（またはStrict）を設定する。セッションタイムアウトを適切な時間（例：30分）に設定する。

**関連インシデント：** BUG-014（ログアウト後のキャッシュ問題と連関）

#### BUG-020　🟠 【重大】氏名・ご要望欄にHTMLタグを入力するとXSS脆弱性が発生する可能性がある

| 項目 | 内容 |
|---|---|
| **ID** | BUG-020 |
| **種別** | セキュリティ脆弱性（XSS）|
| **深刻度** | 重大 |
| **発見テスター** | ③ 意地悪観点、④ セキュリティ観点 |
| **発見日** | 2026-04-27 |
| **対応状況** | ❌ 未対応（動的確認が必要）|
| **対応担当** | TBD |

**概要：** 宿泊予約フォームの「氏名」「ご要望」欄に `<script>alert('XSS')</script>` 等のHTMLタグを入力し、予約確認のBootstrap Modal内でそのまま描画された場合、スクリプトが実行される可能性がある。

**確認手順：**
1. `reserve.html` の氏名欄に `<script>alert(1)</script>` を入力する
2. その他の必須項目を入力し「予約内容を確認する」ボタンをクリックする
3. Bootstrap Modalに氏名がHTMLとして実行されるか確認する

**確認すべきペイロード：**
```
<script>alert('XSS')</script>
<img src=x onerror=alert(1)>
"><svg onload=alert(1)>
```

**影響：** 入力値がHTMLエスケープなしにモーダルに挿入された場合、任意のスクリプト実行・セッションハイジャックが可能になる。

**推奨対応：** すべての入力値をHTMLエスケープ処理して表示する。Bootstrap Modal へのデータ挿入時に `textContent` または適切なサニタイズを使用する。

**関連テストケース：** 手動テスト未対応（REV-032参照）

#### BUG-012　🟢 【軽微】JavaScriptネイティブダイアログとBootstrap Modalが混在している

| ID | BUG-012 | 種別 | 機能（実装品質）| 深刻度 | 軽微 |
|---|---|---|---|---|---|
| 発見者 | ① | 対応状況 | 設計意図の可能性あり | 発見日 | 2026-04-27 |

**概要：** マイページにはJavaScriptのネイティブダイアログ（confirm/alert）が使用されており、予約確認ページにはBootstrap Modal（独自実装）が使用されている。2種類のダイアログ実装が混在しており、UI一貫性の観点から改善が望ましい。ただし、練習サイトとして意図的に多様なUI要素を配置している可能性がある。
