## C. テスト設計観点（プロセス・技法）

## 今後のテストで重点的に強化すべき観点トップ5

| 順位 | 観点 | 理由 |
|---|---|---|
| 1位 | **セキュリティ（B-2）**| 致命的・重大バグ5件（BUG-001〜004/020）が未修正。実システムでは最重要リスク |
| 2位 | **未認証アクセス制御（A-2-09）**| mypage/confirm への直接アクセスが可能。サーバーサイド制御が必須 |
| 3位 | **条件付きバリデーション（A-1-11）**| 確認連絡方法による必須制御の実機未確認。仕様違反の可能性 |
| 4位 | **エラーリカバリーフロー（A-4-03）**| ヒヤリング最重要要求「入力ミスからの回復」が1ケースしかカバーされていない |
| 5位 | **ユーザビリティ（B-4）**| 手動テストでの確認がゼロ。探索テストの発見事項をテストケース化する必要がある |
