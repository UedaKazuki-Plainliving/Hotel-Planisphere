## 1. テストの目的

ホテル予約サイトが、**初めて使うユーザーでも迷わず安心して使えること**を確認します。

今回のテストでは、ユーザークローン（上田 和樹さんのAI模擬人物）のヒヤリング結果をもとに、以下の点を特に重点的に確認します。

| 確認したいこと | 理由（ユーザークローンより）|
|---|---|
| エラーメッセージが具体的で分かりやすいか | 上田さんはエラーが出るとパニックになりやすい（神経症傾向が高い）|
| 金額がオプション変更のたびにすぐ更新されるか | せっかちなので、都度確認できないと不安になる |
| 予約確認ダイアログに入力内容が正しく表示されるか | 「本当にこれで合ってる？」という不安を解消するため |
| プレミアム会員でログインするとプランが増えるか | 限定プランを目的に会員登録している |
| 5人分の人数・金額計算が正しいか | 家族5人（大人2・中学生・小学生・小1）での旅行を想定している |

## 3. テスト環境の準備

### 3-1. 必要なもの

| 必要物 | 詳細 |
|---|---|

| インターネット接続 | Wi-Fiまたは有線でインターネットに接続できること |

| テスト記録用紙 または Excel | テスト結果を記録するため |

### 3-2. Chrome の準備手順

Chromeのインストール・バージョン確認が必要な場合は以下の手順を行ってください。

1. 画面下の「スタートボタン」→「Google Chrome」をクリックして開く
2. Chrome が開いたら、右上の「 **⋮** 」（縦3点）をクリックする
3. 「設定」をクリックする
4. 左側のメニューから「Chrome について」をクリックする
5. 「Google Chrome は最新です」と表示されていれば準備完了

### 3-3. テスト用アカウント

テストには以下のアカウントを使用します。**自分のアカウントは使用しないでください。**

| 種別 | メールアドレス | パスワード | 補足 |
|---|---|---|---|
| プレミアム会員 | `ichiro@example.com` | `password` | 限定プランを確認するテストで使用 |
| 一般会員 | `sakura@example.com` | `password` | 会員種別比較のテストで使用 |

> **注意:** テスト中にパスワードを変更しないでください。他のテスト担当者が使用できなくなります。

### 3-4. テスト前の準備（毎回実施）

1. Chrome を開く
2. 開いているタブをすべて閉じる（新しいタブを1枚だけにする）
3. テスト対象のサイトを開く：  
   `https://hotel-example-site.takeyaqa.dev/ja/`
4. ログイン状態を確認する
   - 右上に「ログイン」ボタンが表示されていれば「未ログイン状態」（OK）
   - 「マイページ」と表示されていたらログイン中なのでログアウトする

## 4. テスト技法の説明

### 4-1. 同値分割法（どうちぶんかつほう）

**一言で言うと:** 「同じ結果になる入力値をグループにまとめて、1グループから1種類だけテストする方法」

**例：パスワード入力欄**

| グループ | 内容 | テストに使う値 |
|---|---|---|
| 有効グループ（OK） | 8文字以上の英数字 | `password1`（9文字）|
| 無効グループA（NG） | 7文字以下 | `pass123`（7文字）|
| 無効グループB（NG） | 空欄 | （何も入力しない）|

7文字のパスワードも3文字のパスワードも「短すぎるNG」という同じ結果なので、代表として7文字だけテストします。

---

### 4-2. 境界値分析（きょうかいちぶんせき）

**一言で言うと:** 「OKとNGの境目の値をテストする方法。バグが出やすい」

**例：パスワードは8文字以上が必要**

| テスト値 | 文字数 | 期待結果 |
|---|---|---|
| `1234567` | 7文字 | NG（エラー）← 境目のひとつ下 |
| `12345678` | 8文字 | OK ← 境目 |
| `123456789` | 9文字 | OK ← 境目のひとつ上 |

「ちょうど7文字」と「ちょうど8文字」の両方をテストします。

**例：宿泊日の受付範囲（翌日〜3ヶ月以内）**

| テスト値 | 期待結果 |
|---|---|
| 昨日の日付 | NG（エラー）|
| 明日の日付 | OK |
| ちょうど3ヶ月後の日付 | OK |
| 3ヶ月と1日後の日付 | NG（エラー）|

## 5. テストレベルの定義

| テストレベル | 目的 | 確認する内容 |
|---|---|---|
| **単体テスト** | 各ページの個々の機能を確認 | 入力欄1つ1つのバリデーション、ボタンの動作 |
| **結合テスト** | 複数ページをまたいだ操作の流れを確認 | ログイン→マイページ確認 など |
| **システムテスト（画面遷移）** | 画面間の移動が正しいか確認 | 画面遷移図に基づく全パターン |
| **システムテスト（ユースケース）** | 実際の利用シーンを再現 | 「上田さんなら実際こう使う」という流れ全体 |
| **システムテスト（非機能）** | スピード・セキュリティ・スマホ対応の確認 | 表示速度、HTTPS、モバイル表示 |

## 7. 合格基準

### 全テスト共通

- テスト手順の「期待結果」に書かれた通りの動作をすること

### 機能テスト（単体・結合・システム）

- エラーメッセージが**日本語で分かりやすく**表示されること
- エラーが起きたとき**何を直せばいいかが分かる**こと

### 非機能テスト

| 種別 | 合格基準 |
|---|---|
| 性能 | ページが **5秒以内** に表示されること |
| セキュリティ | URLが `https://` で始まること |
| セキュリティ | ログイン失敗理由（メール間違い/パスワード間違い）でエラーメッセージが変わらないこと |
| 互換性 | スマートフォン画面サイズ（幅375px程度）でもボタンや文字が見切れず表示されること |

## 8. テスト結果の記録方法

### 8-1. 合否の記入方法

各テストケースの「判定」欄に以下のように記入してください。

| 記号 | 意味 |
|---|---|
| **○（合格）** | 期待結果の通りになった |
| **×（不合格）** | 期待結果と異なった |
| **－（対象外）** | そのテストをスキップした（理由を記入すること）|

### 8-2. 不合格（×）のとき

1. 「メモ欄」に実際に起きたことを詳しく書く  
   例：「"8文字以上で入力してください"の代わりに英語でメッセージが出た」
2. 可能であればスクリーンショット（画面の写真）を撮って添付する  
   - **Windowsの場合:** `Windows キー + Shift + S` を押すと画面を選択して保存できる
   - **Macの場合:** `Command + Shift + 4` を押す
3. テスト責任者に報告する

### 8-3. 不明なとき

「どちらとも言えない」「期待結果の意味が分からない」という場合は  
判定を空欄にしてメモ欄に状況を書き、テスト責任者に確認してください。

## 9. テスト実施上の注意事項

1. **テストは必ず1ケースずつ実施する**。まとめてやらないこと。
2. **テスト前に毎回ブラウザの「更新ボタン」を押す**（古い状態が残らないようにする）
3. **ログイン状態を確認してからテストを始める**（ログインが必要なテスト、不要なテストがある）
4. **テスト用アカウントのパスワードは変更しない**
5. **テスト結果はその場で記録する**（後から記入すると間違える）
6. **不合格の場合はすぐに記録し、次のテストに進む**（自分で直そうとしない）
