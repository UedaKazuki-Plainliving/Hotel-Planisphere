## 1. はじめに（Introduction）

### 1.1 目的

本テスト計画書は、Hotel Planisphereプロジェクトにおけるテスト活動の全体方針・スコープ・スケジュール・リスク・成果物を定義する。テスト対象は練習用ホテル予約サイト（以下「対象サイト」）であり、以下の観点を総合的に検証することを目的とする。

- **機能品質**：会員登録・ログイン・プラン一覧・宿泊予約・マイページの各機能が仕様通りに動作すること
- **非機能品質**：性能・セキュリティ・互換性・ユーザビリティが利用者の期待を満たすこと
- **テスト基盤品質**：ATDD自動テストが継続的インテグレーション（CI）環境で安定稼働すること

### 1.2 スコープの要約

| 区分 | 内容 |
|---|---|
| テスト種別 | ATDD（自動）/ 手動テスト（単体・結合・システム）/ 探索的テスト |
| テスト対象機能 | 会員登録・ログイン・プラン一覧・宿泊予約・マイページ |
| テスト対象外 | サーバーサイドDB・バックエンドAPI実装・ネットワーク構成 |
| テスト環境 | Windows 11 / Chrome（Chromium）/ GitHub Actions（Ubuntu） |

### 1.3 背景と経緯

本プロジェクトは、Selenium/Playwright練習用サイトを題材にATDDによるテスト自動化基盤の構築・評価を目的として発足した。同時に、ユーザークローン（上田 和樹）を用いた要求分析とテスト設計の有効性評価も実施する。

## 7. テストアプローチ（Test Strategy）

### 7.1 テストレベルと手法の対応

```
┌─────────────────────────────────────────────────────┐
│  ATDD（自動・受入）                                   │
│  ・Gherkin形式シナリオ 40件                           │
│  ・CI（GitHub Actions）で自動実行                     │
├─────────────────────────────────────────────────────┤
│  システムテスト（手動）                                │
│  ・画面遷移テスト ST-SC（8件）                        │
│  ・ユースケーステスト ST-UC（4件）                    │
│  ・非機能テスト ST-NF（7件）                          │
├─────────────────────────────────────────────────────┤
│  結合テスト（手動）                                   │
│  ・機能間連携 IT（6件）                               │
├─────────────────────────────────────────────────────┤
│  単体テスト（手動）                                   │
│  ・同値分割 UT（22件）                                │
│  ・デシジョンテーブル DT（10件）                      │
├─────────────────────────────────────────────────────┤
│  探索的テスト                                         │
│  ・5観点（開発者/利用者/意地悪/セキュリティ/使用性）  │
│  ・チャーターベース・仮説連鎖型                       │
└─────────────────────────────────────────────────────┘
```

### 7.2 テスト技法

| 技法 | 略称 | 主な適用対象 |
|---|---|---|
| 同値分割 | EP | パスワード長・電話番号桁数・メール形式 |
| 境界値分析 | BVA | 宿泊日（昨日/今日/明日/3ヶ月後/超過）・人数（0/1/9/10）|
| デシジョンテーブル | DT | 会員登録の必須項目組み合わせ・オプション選択の料金計算 |
| 状態遷移 | ST | ログイン済み/未ログインによる画面アクセス制御 |
| 探索的テスト | ET | セキュリティ・ユーザビリティ・エッジケース |
| シナリオテスト | SCN | エンドツーエンドの利用フロー |

### 7.3 合格基準

| 区分 | 基準 |
|---|---|
| 自動テスト | ATDD全33件（実装済みシナリオ）が全件PASS |
| 手動テスト | 致命的・重大バグが未残存（または対応計画が合意済み）|
| 性能 | 主要3ページ（トップ・プラン一覧・予約フォーム）の表示が**3秒以内** |
| セキュリティ | BUG-001（パスワード平文公開）・BUG-002/003（未認証アクセス）の修正確認 |
| カバレッジ | 全主要機能領域（5領域）にテストケースが存在すること |

> **注記：** 性能基準は ATDDシナリオの「3秒以内」に統一（test_design.md の「5秒以内」はREV-014で要修正）。

### 7.4 テスト中断・再開基準

| 条件 | 対応 |
|---|---|
| CI環境でテストが実行できない | PlaywrightContextの設定を確認し、headlessモード・環境変数を修正してから再開 |
| 致命的バグ（BUG相当）を発見 | テストを中断し、開発チームに即時報告。修正後に影響範囲を再テスト |
| テスト環境（対象サイト）が接続不能 | 最大4時間待機後に再試行。復旧しない場合はテスト実施を翌日以降に延期 |
| テスト実施者の病欠 | 別の担当者に引き継ぎ。手順書（test_cases.md）を参照して継続 |
